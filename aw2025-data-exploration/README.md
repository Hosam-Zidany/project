# AdventureWorks2025 — Data Exploration Reference

المرجع الموحّد لفريق مشروع **Business Intelligence and Decision Support** لفهم قاعدة بيانات **AdventureWorks2025**.

الفكرة: أي سؤال عن البيانات يخطر لأي عضو في الفريق (أو للمشرفين) يجب أن نجد جوابه هنا — إما كنتيجة جاهزة، أو كسكربت يمكن تشغيله، أو كسؤال مفتوح موثّق في `docs/open_questions.md`.

> **حدود النطاق:** لا يوجد Data Warehouse في المشروع. كل الاستكشاف هنا يتم مباشرةً على قاعدة SQL Server التشغيلية المستعادة من ملف `.bak`.
> السكربتات **للقراءة فقط** (SELECT / WITH) ولا تعدّل أي بيانات.

---

## 1) البدء السريع

```bash
# 1. استعادة القاعدة (مرة واحدة) -> انظر 00_setup/README.md
# 2. بيئة بايثون
python -m venv .venv
.venv\Scripts\activate            # Windows   (Linux/macOS: source .venv/bin/activate)
pip install -r requirements.txt

# 3. إعدادات الاتصال
copy .env.example .env            # ثم عدّل DB_SERVER وغيره   (Linux/macOS: cp)

# 4. اختبار الاتصال
python 00_setup/test_connection.py

# 5. تشغيل استكشاف مجلد واحد أو الكل
python 02_sales/explore.py
python run_all.py 02 06           # مجلدات محددة
python run_all.py                 # كل شيء
```

كل سكربت يطبع النتائج في الشاشة ويحفظها في `<المجلد>/outputs/`:
`report.txt` (نص كامل، يُرفع على Git ليقرأه المشرفون دون قاعدة بيانات) + ملفات CSV (لا تُرفع).

## 3) فخاخ يجب أن يعرفها كل عضو

1. **Header ≠ Detail.** `SalesOrderHeader` = طلب (31,465)، `SalesOrderDetail` = بند (121,317). عند الربط يتكرر الطلب بعدد بنوده؛ لا تجمع `SubTotal`/`TotalDue` بعد الربط مع Detail.
2. **2025 سنة جزئية** (حتى 2025-06-29). قارن الفترات المتناظرة فقط.
3. **قفزة الطلبات منتصف 2024** (741 في يونيو → 1,755 في يوليو). تحقق من أنها نمو حقيقي قبل استخدامها في أي نموذج (`05_time_coverage`).
4. **Individual مقابل Store** سلوكان مختلفان (متوسط 2.18 منتج/طلب مقابل 16.01). حلّل كل شريحة على حدة.
5. **التعريفات:** `LineTotal` ≈ `SubTotal` (الإيراد قبل الضريبة والشحن) بينما `TotalDue` يشمل الضريبة والشحن.
6. **الأرقام في التقرير الأول** يجب إعادة التحقق منها (`12_metric_definitions` يفعل ذلك آلياً).
